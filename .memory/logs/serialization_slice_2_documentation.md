## Post-reconciliation ATC findings (found and fixed this pass, commit `f9d0a070`)

Ran `SAPDiagnose(action="atc")` against every corrected object as the
task's Phase 0 gate requires. Findings, all priority 3 (SLIN warnings,
non-blocking for activation but required for a clean ATC gate):

```text
ZCL_ABAPGIT_ORTEC_SER_ORCH:    3x "Empty documentation is not allowed"
                                 (MESSAGE G4J) - empty @raising tags on
                                 dispatch_batch/handle_receive_failure/
                                 route_to_sequential_fallback
                                3x "ABAP Doc comment is in the wrong
                                 position" (MESSAGE GDT) - TYPES: BEGIN OF
                                 ty_dispatch/ty_resolved/ty_outcome
ZCL_ABAPGIT_ORTEC_SER_COST:    2x MESSAGE GDT - ty_estimate/ty_ewma
ZCL_ABAPGIT_ORTEC_SER_PLANNER: 2x MESSAGE GDT - ty_work_item/ty_batch
ZCL_ABAPGIT_ORTEC_SER_PROV_GEN: clean
ZABAPGIT_ORTEC_SERIAL (FUGR, incl. FM): clean
ZAOG_SER_BATCH_RESULT/_TT, ZAOG_SER_TADIR/_TT: clean
```

Root cause (confirmed against an existing working example in this
codebase, `zcl_abapgit_ortec_obj_store.clas.abap` line 304): ABAP Doc
(`"!`) cannot correctly attach to a CHAINED `TYPES: BEGIN OF x,` colon
statement - it must precede an UNCHAINED `TYPES BEGIN OF x.` statement,
with each field declared as its own `TYPES field TYPE type.` statement
and the block closed with `TYPES END OF x.`. All 7 occurrences (3x ORCH,
2x COST, 2x PLANNER) converted to this form; the 3 empty `@raising` tags
were given real descriptive text. Fixed locally in `f9d0a070`, NOT yet
re-verified against a live ATC run (requires owner import/activate first
since ATC reads the system's active version, not the local file).
